# 基于合成数据增强与知识蒸馏的英语作文智能批改系统

> **项目简介**：以 Qwen3-1.7B 为学生模型，通过合成数据增强、离线响应知识蒸馏和 QLoRA 多任务监督微调（SFT），开发英语作文智能批改系统，研究高质量合成反馈能否改善小参数模型的垂直领域适配能力。

## 开工前必读：当前模型与交接

**已决定统一使用官方 `Qwen/Qwen3-1.7B`。** A 是未经本项目微调的官方原版，B 和 C 从同一原版分别训练。本轮采用 A/B/C 三组，取消 D（筛选后教师数据对照）；旧 Qwen2.5-0.5B 仅作历史版本。先读 [模型迁移与入口状态](docs/model-migration.md)、[最新评测摘要](docs/member5/evaluation-status.md) 和 [Windows 交接](handoff.md)。格式跑通与评分质量改善分别验收。

当前工程交付：已接入本地 Qwen3 模型 B，并提供“英语作文批改工作台”桌面窗口、任务耗时、报告导出与人工复核。详见 [6号系统交付](docs/member6-week34.md)、[A/B/C复现入口](docs/member5/abc-evaluation.md) 和 [人工评价操作](docs/human-evaluation.md)。正式真人评价由6号与另一位评价者独立完成，评分尚未填写；权重、EXE、真实预测和评价材料通过内部核对包交付。

## 🛠️ Git 协作规范（所有人必读）

为了保证项目顺利集成，请所有人严格遵守以下开发规范：

1. **分支管理**：绝对**不允许**直接在 `main` 分支上提交代码。所有人必须在自己的分支（如 `feat-data-processing`）上开发，完成后提交 Pull Request (PR)，由 1 号审查后合并。
2. **密钥安全**：**严禁**将大模型 API Key、Token 等敏感信息上传至 GitHub。请在本地使用 `.env` 文件配置，并确保 `.gitignore` 中包含了 `.env`。
3. **大文件处理**：**严禁**将模型权重（如 `.bin`, `.safetensors`）、大型数据集（如 `.csv`, `.jsonl`）直接推送到 GitHub。大文件请统一上传至网盘或使用 Git LFS，并在群内共享链接。
4. **提交信息**：Commit message 请尽量清晰（如：`feat: 添加数据清洗脚本`, `fix: 修复推理接口报错`）。

## 三任务评测（2026-11-09 开发，2026-11-20 交付功能分支）

评分使用 MAE/RMSE/QWK；反馈支持 ROUGE/BLEU、可选 BERTScore，以及兼容 6 号量表的人评/外部裁判记录汇总；纠错支持 ERRANT P/R/F0.5 的全文参考与已对齐 M2 两种入口。详见 [评测工具说明](evaluation/README.md)。反馈参考相似度不等于内容正确率，人工或外部裁判评分须独立核验；尚无付费裁判 API 自动调用。评测 BERTScore 环境应与 Gradio Web 环境分开。

## 当前代码入口与取得方式（2026-11-26）

GitHub main 在 `8020036` 已包含三任务评测工具。复跑 6 号的实验另需取得模型适配器、原始预测和训练日志。

- `train_qlora.py`：main 带入的 Qwen3 训练入口，默认长度512；正式使用前核查过滤后各任务数量、实际训练batch的labels及启动参数。
- 根目录 `inference.py`：复用Qwen3加载与生成函数，已修正`--limit=-1`漏样本；默认仍读取test。验证及可续跑同条件比较使用`scripts/run_abc_evaluation.py`，显式冻结输入、版本和样本范围。
- `balance_data.py`：对原始评分分布做删减/复制的重采样脚本，**不是**2号的教师数据混合程序；其输出与原始数据版本、采样倍数须单独记录。
- `inference/model_pipeline.py`：当前Qwen3三任务本地接入口，支持B Adapter、任务校验、耗时和独立GPU进程；机器路径使用被Git忽略的本机配置。

跨电脑使用时，从 6 号的核对包获取权重和逐条运行记录，仓库提供 [不含作文原文的评测摘要](docs/member5/evaluation-status.md)。
