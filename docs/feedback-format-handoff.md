# 1、3、4、5、6 号：反馈格式统一说明

更新日期：2026-11-03。当前决定：教师反馈直接模仿 LEAF，人工与教师使用相同任务指令和答案结构，不再要求细粒度字段。

## 统一接口

user 内容为以下指令，接两个换行和作文原文：

```text
Provide feedback on the following English essay. Return a JSON object with a feedback string.
```

assistant 回答仅为：

```json
{"feedback":"一段针对该作文的英文反馈"}
```

feedback 必须是非空英文字符串。总体评价、问题说明和建议都写在这段文字中，不另外输出 summary、suggestions、original、corrected、explanation 或 errors 字段。禁止用教师分数替换人工评分。

## 各成员开工时怎么做

| 成员 | 按此约定执行的工作 |
|---|---|
| 3 号 | 正式教师数据尚未生成，直接按新格式生成；使用新 LEAF 配置和独立运行目录。C 是基础格式合格数据；D 进一步人工审核反馈正确性、具体性与忠实度。新格式不再检查局部引用位置。 |
| 4、5 号 | 原始 LEAF 样本不改，教师样本使用相同 user 指令及 feedback 字符串答案；训练只读取 messages，不把来源和审核信息作为答案。采样比例与训练预算另行共同确认。 |
| 1 号 | 按此接口组织反馈推理与输出校验；评分与纠错是独立任务，不要求反馈模型单次输出整份报告。 |
| 6 号 | 网页开工/接入模型时直接展示 feedback 整段文字，不依赖 errors 数组或精确原文定位；评分另显示六维结果，纠错另显示完整纠正文本。 |

是否已经开工不影响此约定：尚未开发的直接按新接口做；若复用仓库旧原型，按新接口适配。此文档不将 6 号的实际工作进度视为已确认事实。
