## 1. 数据混合交付

- 输入：明确版本的原始 train 文件，以及 3 号交付的新版 LEAF 教师候选。教师生成和内容筛选仍由 3 号负责；2 号不以教师分数替换人工分数。
- 只读训练划分，不混入 validation/test；保留原始 ID、来源、教师模型/提示版本和筛选依据，核查重复及跨集合泄漏。
- C/D 使用相同原始数据、等量教师候选 N，不能用“混合行数相同”代替训练预算相同。N、采样与训练预算由 5 号与 4 号确认，未确认项不可自行写死。
- 输出：C/D 训练 JSONL、配置/种子、输入版本指纹、各任务与各来源数量、重复/泄漏检查及长度统计。细节见 [混合方案](../member5/data-mixing-plan.md)。
- D 沿用已确认的现有审核凭证要求；本交接不改筛选政策，也不把待审核候选冒充已接受训练数据。

## 2. 批量推理交付

- 使用相同数据划分、任务指令和已记录的推理参数，保存模型/适配器检查点、tokenizer/模板、版本和生成配置。先用 validation 小批次联调，规则冻结后再做 test。
- 每条至少保存 id、task、raw_output；raw_output 是模型新增生成部分的原始回答字符串。失败保留 ID、status=error 和错误记录，不修复、不删除、不把参考答案写进预测。
- 分别保存评分、反馈和纠错结果，或提供可明确拆分的原始清单；每个评价文件对应一个模型、一个任务与一个划分，避免其他任务 ID 被计为额外预测。
- 4 号之前的附件使用 pred_raw，本地可忠实转列名；统一接口优先 raw_output。不要截取第一段 JSON 来隐藏尾部乱码。
- 小批次确认加载、生成和保存流程后再扩量；“程序接通”不要求 Base A 每条遵守格式，真实输出失败必须如实保留。说明见 [评测入口](../../evaluation/README.md)。

## 3. 图表与数据整理交付

- 从 evaluation 的报告和逐样本记录读取指标，不重算出不同口径；评分保留小数。null 不当作 0，未运行模型不补造柱子。
- 同时展示样本数、覆盖率/失败率、数据划分与模型版本。自定义失败惩罚 MAE 与普通 MAE 分开标注；不同有效子集不可无说明比较。
- 输出图表、可追溯汇总表及生成方法；5 号负责评价结论与误差解释。其他任务指标另图说明，不混淆相似度和内容正确性。
