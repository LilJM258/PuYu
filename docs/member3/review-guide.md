# 人工抽检与 Markdown 标记

3 号牵头审核教师合成反馈，6 号可协助统一口径和讨论疑难。最终学生模型的独立效果评测是另一个环节。

## 如何标记

本地运行数据产生的阅读版位于 results/review_week1/。打开 index.md，再进入对应编号的 Markdown 文件，编辑末尾的人工填写区。例如以下仅示范格式，不代表任何实际样本的判断：

```text
- 接受 / 拒绝 / 待定：拒绝
- 是否虚构错误（是 / 否 / 不确定）：不确定
- 改法、解释或遗漏的具体问题：该改法改变了原句的否定含义，需要确认作者原意。
- 审核人：3号
```

保存后告知助手修改的编号即可；同一共享工作区中无需重新上传文件。若在另一台电脑修改，再把修改后的 Markdown 发回。

不要改写原文或教师原始反馈。需要纠正错误时写在人工填写区；如果将来制作人工修订数据，应另存版本并说明处理策略。

## 判断标准

- 接受：判断和改法总体可靠，解释合理，保留原意；不因只是自动通过而接受。
- 拒绝：有明确误报、错误修改、严重解释错误或原意改变，记录具体证据。
- 待定：无法判断作者意思或语言问题，保留疑问，不强行接受。

空错误列表不必然失败；风格偏好不能直接称为语法错误。整段改法要放回上下文核对，尤其留意否定、时态、观点和事实。

Markdown 阅读版不是自动回写工具。只有人工明确给出的结论和评分才可录入源审核 JSONL；未提供的评分仍为空，助手初查不能记为真人评分。

JSONL 中 decision 使用 pending/accept/reject，完成时注明 reviewer 和 hallucinated_error；四项 1～5 分可按问题识别、具体性、修改有效性、原意忠实度填写，不适用时为 null。

## 抽样和费用

试生成阶段可先做小规模内容核查，手册没有规定第一周必须逐条人工核完所有作文。第三周 100～200 条抽检是后续正式筛选任务。

自动样本按规则通过、规则拒绝、基础拒绝分层取样；各层分别报告，不能把合并接受率直接当总体准确率。平台实际账单另行核对，程序的报价情景估算不等于真实扣费。
