# LEAF / FeedEval 原始来源核查

核查日期：2026-11-05；仅研究，未改项目代码。

## LEAF

原论文同时报告 BERTScore、ROUGE-1/2/L、BLEU，以及人工五维 1～3 分：准确相关、指出弱点、指出优点、具体可操作、总体帮助。实验为 20 篇作文 × 四系统，每份反馈双人评分后平均。附录 B 有具体分档。优缺点维度部分按提及数量计分，本项目可借鉴但应防止鼓励无必要地挑错。当前公开数据是第二版，仅保留 Mary Rose 评论，不能混用论文第一版统计。

- [LEAF 原论文：表 2/3、第四节、附录 B](https://aclanthology.org/2024.naacl-short.36.pdf)
- [当前第二版作者仓库](https://github.com/EducationalTestingService/LEAF)

## FeedEval

三维为具体性、可操作帮助、与评分等级描述一致性。原版须训练三个评价器：前两者为排序奖励模型，后者为自然语言推断模型；不是通用大模型提示词打分。主要在 ASAP++ 按 trait 反馈验证，同作文候选内 softmax 分数不能当跨作文绝对 1～5 分。人工验证另用“忠实、修改有用、rubric 一致”三维 1～5 分。代码和数据入口公开，未核实即用权重。迁移到 LEAF 须人工校准。

- [2026 年 7 月正式论文：第三、四节、算法 1、附录 K.3](https://aclanthology.org/2026.findings-acl.615.pdf)
- [公开代码与数据入口](https://github.com/BBeeChu/FeedEval)
- [specificity 训练代码](https://raw.githubusercontent.com/BBeeChu/FeedEval/main/srcs/specificity_evaluator.py)
- [validity 训练代码](https://raw.githubusercontent.com/BBeeChu/FeedEval/main/srcs/validity_evaluator.py)

## 项目应用边界

保持现有 `{"feedback":"整段反馈"}`，这些方法无需把学生输出改成细粒度字段。可用参考相似度作辅助、人评作内容依据，必要时增加经人评校准的 LLM 裁判；普通提示词裁判不可宣称为原版 FeedEval。这里讨论的是独立测试集上的模型反馈评价，不等于要求对教师训练集 D 逐条人工审核，两项政策应分开。

## 其他方案

### 参考相似度

BERTScore 用上下文向量比较候选与参考的 token 相似度；P/R/F1 不是“反馈指控正确率”。作者实现提醒记录模型、层数、版本及长文本截断。与 ROUGE/BLEU 一样，默认比较反馈与参考，不直接读取作文验证建议。建议作为辅助指标，不独立证明内容质量。

来源：[BERTScore 原论文](https://arxiv.org/abs/1904.09675)、[作者实现](https://github.com/Tiiiger/bert_score)。

### 大模型裁判与条目满足率

G-Eval 按评价标准让大模型评估生成文本，并指出可能偏好大模型生成文本；主要验证摘要和对话，迁移作文任务须本地校准。[G-Eval 论文](https://aclanthology.org/2023.emnlp-main.153/)

RFE 作文反馈方案让裁判判断覆盖、证据、忠实、安全四类共 166 个二元条目，按权重汇总满足比例。条目依赖 ASAP 题目及评分上下文；不能原封不动套到 LEAF。截至核查时，作者仓库仅提供 README，声明录用后发布代码与数据，不能承诺开箱即用。[RFE 预印本](https://arxiv.org/html/2607.19219v1)、[作者仓库](https://github.com/hellomuyi/RLAES)

### 成对比较与修改效果

同作文匿名比较两份反馈，可统计胜、平、负；交换左右顺序检查位置偏差。固定同一修改者、分别按反馈修订后，再比较修改质量也是可选补充。FeedEval 做了修订效果验证，但模型修改者的效果不能直接当真实学生学习收益。[FeedEval 论文](https://aclanthology.org/2026.findings-acl.615.pdf)

## 对本项目的具体建议（待用户讨论，未实现）

1. 保留 LEAF 字符串目标；评测程序另存评价分数，不要求学生生成评审字段。
2. 在同一批独立作文上比较 A/B/C/D。对有人工参考的样本，可用 BERTScore F1，并可辅以 ROUGE-L；参考反馈不是唯一正确答案。
3. 内容质量建议评价正确性、针对性、可操作性、原意忠实度。若采用 1～5 分，则是本项目拟定量表，不是 LEAF 原版量表或原版 FeedEval。
4. 先明确各档标准及反例，再让人工或固定大模型裁判评价。裁判必须看原文；缺少题目/rubric 时不猜测，不强评无法核实的题目贴合度。
5. 先用例如 20～30 篇独立校准样本、两位人评检查裁判一致性；这是试运行建议，不是统计效力保证。正式测试前固定规则、裁判版本及提示词，匿名模型身份，保留理由和证据。
6. 报告逐维分数、样本数和失败率。评审调用失败与学生生成失败分别记录；严重误报比例需明确判定规则。后续可按同作文配对统计和置信区间比较。
7. 教师训练集筛选与学生最终评价分开；避免同一教师自评成为唯一证据。本次不决定 D 的审核政策。

本次只完成文献研究，未添加评测代码、安装模型、调用付费教师 API 或改动实验配置。以上建议尚未选定，不作为已实施标准。
