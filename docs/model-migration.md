## 当前入口及已知限制

| 文件 | 当前用途 | 使用前必须知道 |
|---|---|---|
| train_qlora.py | Qwen3-1.7B QLoRA训练 | 默认长度512且超长整条删除；microbatch1、累积8、学习率2e-5；max_steps默认10且恰为10时只取前20条。真实batch的labels与EOS监督依赖版本，需验收 |
| 根inference.py | Qwen3批量生成，支持加载adapter | 已注释no_repeat_ngram_size=4，软重复惩罚1.05；硬编码test、默认limit=-1的实现漏数据；强制离线，需要本地权重缓存 |
| balance_data.py | 原始评分分布重采样 | 对中间均分段随机删减、其他段重复采样；保留其他任务，不含教师混合。使用会改变样本/任务分布，不能无记录当成同一训练集 |
| inference/model_pipeline.py | 旧Qwen2.5和旧评分字段原型 | 不作当前模型正式推理入口；本次未为替换模型而直接改队友运行代码 |
| evaluation/ | 独立评分、反馈、人评和纠错工具 | 见 [使用说明](../evaluation/README.md)，不依赖网页mock |

根inference.py的limit问题可纯Python复现：`half = -1 // 2`得到-1，`items[:-1]`会丢掉最后一条，而非表示全量。因此当前本地3070条test会按两任务池选到3068条。小正数limit也不是三任务全覆盖，奇数会少一条，非评分池会混入纠错。该限制应由批量推理负责人明确处理；本次仅记录，没有修改其代码。

根脚本默认test是正式测试方向；开发联调应改成明确的validation输入。不要为“跑通”将test作为训练或调参数据。根inference.py所有生成完成才写文件、w模式会覆盖旧文件，实际运行还需避免结果丢失或覆盖。

## 训练验收重点

1. 核对实际启动命令、数据版本和最终步数，区分10步试跑与正式训练；不要只引用代码默认值。
2. 在Trainer实际batch上检查用户输入为-100、完整目标答案及真实结束符参与loss、padding不参与。已在旧默认collator路径复现风险，新版可保留labels，不能认定当前训练一定出错。
3. 统计长度过滤后各任务/来源数量。本地原始9252条在官方分词器默认1024下保留8973条，512下保留2857条（评分1328、反馈387、纠错1142）；不是队友实际日志。改长度和累积会改变数据与预算。
4. 对照A/B时固定输入与生成设置。已复现的4-token禁重复会阻挡合法JSON，新main已注释该参数；最新预测是否来自本次代码及何配置仍需确认。
5. C/D混合由2号实现、5号确认规则。用户最新希望总体原始∶教师约1∶1，N、总规模、任务比例与预算仍未定案；必须在长度过滤/重采样之后重新核对比例。

## 重采样不等于数据混合完成

balance_data.py读取原始两份train并写train_balanced.jsonl；其中重复ID可能表示有意的训练采样倍数，不是新作文。记录原始唯一ID数、复制次数、随机种子、过滤后各任务数。当前日志的“原始总数据量”不计被删去的中间分记录，不能当成完整9252条输入计数。是否使用该文件训练了最新B，尚未取得命令和日志确认。

本次只对同步文件做静态/算法检查，不运行重采样脚本生成新数据、不启动GPU训练、不声称正式A/B/C/D实验完成。
